# Reference PRDs

What a good BA analysis of each ticket in `../tickets/` should produce, written
by hand from the knowledge base (`leavedesk-knowledge`). Uses:

- compare with the PRD the BA workflow writes (did it find the same rules and
  ask the same questions?);
- a fallback: paste one into a ticket's description to run the Dev workflow
  without the BA step (e.g. to save time in the workshop).

They build on each other in order: F01 → F02 → F03 → F05; F04 any time after
F02; F06–F10 after F01–F05. The `data-testid`s are shared with the QC test
cases, keep them.
